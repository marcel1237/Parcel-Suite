# Build Generic de produção do PlayOS Noble 6.8.4

Data: 18 de agosto de 2026

## Resultado

O kernel Ubuntu Noble 6.8.4 com o patchset FreeBSD/PlayOS compilou com sucesso
a partir da configuração `amd64-generic` exportada das `annotations` oficiais
da própria árvore Ubuntu. Foram concluídos `bzImage`, módulos, BTF dos módulos,
assinatura de build, `modules_install`, `depmod` e initramfs genérico.

Esta validação substitui, para cobertura de configuração, o primeiro build
baseado em `x86_64_defconfig`. Ela ainda não transforma a árvore em Ubuntu
Resolute: o fonte local é Noble 6.8.4 apesar do nome histórico da pasta.

## Identidade e diretórios

- fonte principal: `Kernels/ubuntu 26 resolute kernel`
- fonte de build sem espaços: `/home/marcel/kernel-work/playos-noble/source`
- saída Kbuild: `/home/marcel/kernel-work/playos-noble/out-generic-prod`
- staging de módulos: `/home/marcel/kernel-work/playos-noble/stage-generic-prod`
- release produzida: `6.8.4-playos-freebsd-lab1+`
- patches da série: 8

O caractere `+` indica uma árvore modificada/não commitada. Portanto esta
release continua sendo candidata de laboratório, não uma release assinada do
produto.

## Configuração

A configuração base foi exportada de `debian.master/config/annotations` para
`amd64-generic` e recebeu somente o fragmento de produção PlayOS. Os pontos
verificados incluem:

- `CONFIG_TLS=m`, preservando a política modular do Ubuntu;
- `CONFIG_SECURITY_APPARMOR=y`;
- `CONFIG_SECURITY_LANDLOCK=y`;
- `CONFIG_DEBUG_INFO_BTF=y` e `CONFIG_DEBUG_INFO_BTF_MODULES=y`;
- `CONFIG_FAULT_INJECTION` desativado no perfil de produção;
- certificados Canonical gerados pelas regras oficiais em `debian/rules`;
- fragmento de laboratório, fault injection e sanitizers não foram misturados.

Rust não foi ativado. O Linux 6.8 desta árvore exige rustc 1.75.0 e bindgen
0.65.1, além da fonte de `core`; a toolchain Resolute disponível localmente é
rustc 1.93.1/bindgen 0.72.1 e não é compatível com o gate `rustavailable`.
Desativar Rust explicitamente foi preferível a produzir uma configuração
aparentemente Generic com uma toolchain não suportada.

## Correção adicional descoberta

O build Generic exercitou `tools/lib/bpf` e revelou um erro sob GCC 15:
`strchr()` recebia uma string constante e seu retorno era atribuído a
`char *`. A variável agora é `const char *`. A correção existe na fonte e no
patch `0107-libbpf-preserve-const-path.patch`.

## Avisos e riscos conhecidos

O build terminou com código zero, mas registrou avisos que devem entrar no gate
antes de uma release:

- dois IDs BTF LSM não resolvidos: `bpf_lsm_task_getsecid_obj` e
  `bpf_lsm_current_getsecid_subj`;
- aviso de fortify no Nouveau `r535_gsp_rpc_set_registry`;
- frame de 1.048 bytes em `stmmac_test_irq_multi_msi`, acima do limite de
  aviso de 1.024 bytes;
- dracut não pôde atualizar o cache global read-only de `console-setup` nem
  executar `fsfreeze`, mas concluiu com código zero e a imagem foi inspecionada.

Esses avisos pertencem ao baseline Ubuntu 6.8 compilado com a toolchain atual;
não foram introduzidos pelas adaptações FreeBSD, mas ainda precisam de triagem.

## Selftests finais

O kit final foi executado pela cópia de build em caminho sem espaços e retornou
quatro grupos PASS: `sendfile` sobre AF_UNIX, Landlock ABI 8, inventário de
recursos e isolamento (cgroup v2, namespaces, seccomp, PSI e AppArmor). Fault
injection retornou SKIP, como esperado no perfil de produção. Esses testes
rodaram no kernel host 7.0 e comprovam o kit, mas não substituem sua repetição
depois do boot do kernel 6.8.4 recém-gerado.

O Kselftest continua incompatível com o caminho principal que contém espaços;
por isso a área `/home/marcel/kernel-work/playos-noble/source` permanece um
requisito operacional de build e teste.

## O que continua pendente

- boot do kernel e initramfs em QEMU/KVM;
- execução dos selftests dentro do novo kernel, não somente no kernel host;
- pacote Debian instalável e integração com hooks do Ubuntu;
- chave definitiva, assinatura para Secure Boot e política de rotação;
- teste em hardware de GPU, Wi-Fi, áudio, suspend/resume e armazenamento;
- benchmark comparativo e regressão contra um build Noble Generic sem patches;
- eventual migração separada para fonte Ubuntu Resolute/Linux 7 quando ela for
  adicionada ao projeto.

QEMU não está instalado e a instalação global exige autenticação sudo
interativa. Nenhum kernel, módulo ou entrada do GRUB foi instalado no host.

## Conclusão

O patchset está correto para prosseguir como laboratório Noble: ele compila no
perfil Generic de produção e preserva os mecanismos Linux equivalentes
selecionados. Não está correto chamá-lo de pronto para produção antes de boot,
testes internos, empacotamento e matriz de hardware.
